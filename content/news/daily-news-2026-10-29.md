## 一、AI 行业动态

**Gemini 4 Carbon 正式发布：登顶智能指数，网络安全成了核心卖点（10.29）**

距上一代 Argon 仅两周，谷歌推出新一代前沿模型 Gemini 4 Carbon，在 Artificial Analysis 智能指数 v5.0 上以综合 59 分位列第一，领先 Claude Opus 5.5（58 分）与 GPT-6 Astra（57 分）。它专为长周期智能体任务设计，可连续多日自主完成根因分析与系统级代码修复；在自主漏洞挖掘评测 SEC-bench Pro 上以 88.2% 成功率居首。因具备攻防兼备的网络能力，目前仅通过 Fairwind 计划向受审核的网络安全防御者开放，API 首发价每百万 Token 输入 2 美元、输出 10 美元，缓存输入享 95% 折扣。把"安全能力"当作旗舰模型的头号卖点，这是第一次。

**财报夜分化：微软盘后大涨，谷歌盘后跌超 10%（10.29）**

同一晚两份财报，市场给出了相反的答案。微软 Azure 增速加快到 48%，资本开支反而低于预期，盘后大涨；谷歌云收入翻倍，自由现金流却连续两个季度为负，盘后跌超 10%、蒸发逾 2800 亿美元市值。同样是重金押注 AI，市场开始用真金白银区分"花得值"与"烧得慌"——投入本身不再是利好，投入的效率才是。

> 注释：**自由现金流** 企业经营活动赚到的现金，减去维持和扩张业务必须投出去的钱后，真正能自由支配的部分。它为负，意味着赚的钱不够覆盖扩张的开销，要靠融资或借款补上。

**OpenAI 转向谷歌 TPU：算力供应链再"去英伟达化"一步（10.29）**

据 The Information 报道，OpenAI 计划采购谷歌的 TPU 芯片。此前 OpenAI 已在半年内把模型铺上 Azure、AWS 与 Google Cloud 三家云，如今又在选择自研芯片之外的第二条算力来源。对一家把"算力即战略"写在脸上的公司来说，多一个供应商就多一分议价权——英伟达的独家位置，正在被一点点挪松。

**智谱 AutoGLM：让 AI 直接上手操作手机（10.29）**

智谱推出自主智能体 AutoGLM，可代替人类控制电子设备：无需动手即可完成点外卖、朋友圈点赞、高铁购票等常见手机操作，还能自主执行超过 50 步的长步骤任务并跨 App 协作；基于屏幕截图输入的 GLM-PC 已启动内测——它不需要 HTML 等文本信息，只看画面就能操作。A 股市场随之出现"智谱 AI 概念"逆市上涨。当 Agent 长出手和眼睛，操作系统的入口之争就重新开始了。

**SK 海力士 Q3 营收破 100 万亿韩元：HBM 产能已售罄至 2029 年（10.29）**

SK 海力士第三季度营收首次突破 100 万亿韩元、创下纪录，营业利润 83.3 万亿韩元超预期。公司称 DRAM 与 HBM 产能已售罄至 2029 年，关键存储组件供应短缺至少持续到 2030 年。这条消息的另一面是：未来几年算力扩张的天花板，可能不在 GPU，而在它旁边那几颗存储芯片。

**一句话总结：今天的主线是"验收"——榜单在重排考场（v5 指数）、财报在验收投入（微软与谷歌）、市场在验收供应（HBM 售罄至 2029）：AI 从"谁投得多"进入"谁花得值"的阶段。**

## 二、AI 新元素

**阿里领投：AI 评测与合成数据公司 UniPat AI 获约 3 亿美元融资（10.29 深读）**

成立不到一年的中国 AI 评测与合成数据初创公司 UniPat AI 被曝即将完成约 3 亿美元融资，由阿里巴巴拟领投，腾讯、红杉中国等跟投，估值飙至 25 亿美元。创始人李宽是一名 90 后，香港科技大学博士，去年还在阿里通义实验室做后训练与数据合成。在他身后，前字节 Seed 成员创办的智能知识、前 MiniMax 骨干创办的 Copula Lab、获红杉与 BAI 及鼎晖连轮押注的原壤智能密集浮出水面。

> **它怎么赚钱？** UniPat 卖的是大模型时代最缺的两样东西：干净的考卷和管够的练习题。一方面它做第三方评测——像会计师事务所之于企业财务，为模型公司、投资机构和企业采购方提供"不掺水"的能力评估，按评测项目与订阅收费；另一方面它做合成数据，为后训练与强化学习批量生产高质量、可控分布的数据，按数据量或定制任务计价。上游是各家模型公司公开与私有的能力边界（评测要看得准），下游既是模型厂商也是采购模型的企业客户。有意思的是它的中立性生意：当模型公司既是运动员又是裁判员，一个第三方考场的价值就水涨船高——这也解释了阿里为什么一边自研模型、一边投评测公司。25 亿美元估值押的是：模型会越来越多，能信的分数只会越来越少。

**扩散语言模型杀进 Agent 主场：Clover-35B 中位执行 1.52 秒（10.29）**

扩散智能发布 Clover-35B-A3B-Preview，一个 350 亿参数的 MoE 架构扩散语言模型。在网页 Agent 评测中，它的中位执行时间为 1.52 秒，比 Jev 快一倍多，尝试成功率达 98.6%。与逐词生成的自回归模型不同，扩散语言模型以并行去噪的方式产出文本，在延迟与吞吐上有结构性优势。这条线在沉寂多年后，正在 Agent 需要"快"的场景里重新找到位置。

**谷歌开放 Android Studio：一次接入 40 多个第三方编程智能体（10.29）**

在 Android Dev Summit 上，谷歌宣布 Android Studio Rabbit 2 采用开放的智能体客户端协议（ACP），推出"Bring Your Own Agent"——开发者可以把任意支持该协议的第三方 AI 编程智能体接进官方 IDE。过去 IDE 厂商都想自己做那个唯一的 Agent，如今最大的一家主动把入口让出来：与其赌谁家模型强，不如把自己做成所有 Agent 都要走的那道门。

**实时交互视频赛道升温：一张新榜让 38 个模型现出原形（10.29）**

实时交互视频是今年最热的方向之一：阿里推出 HappyOyster，昆仑万维发布 Matrix-Game 4.0，爱诗科技发布 PixVerse R2，生数科技 7 月推出 Vidu S1、9 月又发 Vidu S2，资本也在跑步入场。但这个赛道连名字都没统一——有人叫它"交互世界模型"，有人说它是第三条路线。清华大学、英伟达、CMU、UC Berkeley、普林斯顿、NUS 等机构联合推出 StreamEval，首次为它建立评测基准：覆盖数字人对话、虚拟人表演、世界生成、指令编辑与参考编辑五类任务，已评测 38 个模型并公开榜单、代码与数据集。结果不太好看——最高分仅 15 分。

**大模型首次试水双 11：词元成了独立品类（10.29）**

今年双 11，大模型首次试水电商变现，词元（Token）作为独立品类进入大促。把"每次调用"摆上货架卖，是模型公司第一次真正按零售逻辑做生意：它需要解决的是定价、套餐与售后这些零售业的古老问题，而不只是跑分。

> 注释：**扩散语言模型** 不像主流模型那样一个字一个字往外蹦，而是先把整段文本"涂成噪声"再一步步去噪还原，可以并行出词。代价是控制难度更高，好处是延迟与吞吐天然占优。

**一句话总结：新元素都在补"看不见的那层"——考卷（UniPat）、速度（Clover）、入口（Android Studio）、标准（StreamEval）、货架（双 11 词元）：热闹的是模型，卡住的是这些。**

在 The Information 的 WTF 峰会上，高盛投行联席主管 Kim Posnett 表示，她对 AI 整体"极度看多"，但投资人正变得更谨慎——随着资本成本上升，市场开始出现裂缝。她特别强调："这不是 AI 情绪的转变。"换句话说，钱还在，只是不再闭着眼睛给。这与当晚微软、谷歌财报截然不同的市场反应，恰好是同一件事的两面。

> 注释：**纵深防御** 不依赖单一防线，而是层层叠加：模型对齐是一层，实时监测是一层，沙箱隔离是一层，企业侧控制权又是一层。任何一层被绕过，后面还有几层兜着。

**一句话总结：大 V 们今天在给"进步"加注脚——皮查伊和布林说进展很快但远未到终局，唐杰说该学的是人不是数据，波斯内特说钱变挑剔了，梁文锋的成绩单则提醒：单项第一和综合领先，是两件不同的事。**

## 四、GitHub 项目精选

**Warp：把终端改造成 Agent 开发环境（单日涨星约 12,800）**

Warp 是一个把传统终端重做成"Agent 开发环境"的项目，近期单日涨星约 12,800，成为当日 Trending 上最受关注的项目之一。它的思路很直接：既然编码 Agent 主要在命令行里干活，那就让终端本身成为承载 Agent 的地方——命令、输出、会话与 Agent 的执行过程放在同一个界面里管理，而不是让 Agent 寄生在一个聊天窗口里再往外敲命令。为什么有趣：Agent 越能干，人与它的协作界面就越成为瓶颈。终端是所有开发者都已有的习惯，把它升级而不是替换，是阻力最小的一条路。

**VibeVoice：微软开源的语音 AI（单日涨星约 1,600）**

微软开源的语音 AI 项目 VibeVoice，发布当日涨星约 1,600。它把语音合成与相关能力以开源形式放出，让开发者可以在本地或自有服务里搭建语音交互链路，而不必把音频数据交给第三方 API。为什么有趣：语音是这轮 AI 里商业化最顺的品类，却也是数据最敏感的品类之一——声纹属于生物特征信息。大厂把这条能力开源，等于把"能不能用"和"敢不敢用"两道题一起往前推了一步。

**morluto/rea：让 Agent 去逆向工程一切（约 397k 星，单日 +5,167）**

rea 是一个把 AI Agent 接到逆向工程工具上的项目，可以从应用的行为一路分析到原生二进制，覆盖 app、二进制与代码，全部在本地完成，通过 MCP 与 Claude Code 等环境协作。为什么有趣：过去逆向工程是少数资深工程师的手艺活，门槛高、可复用性差；把它交给能持续试错、不知疲倦的 Agent，等于把一项专家技能变成了可批量执行的工作流。它也代表了一类正在成型的开源资产——不是给 Agent 更多知识，而是给它更多"手艺"。

## 五、今日技巧：给长流程任务加一组"中途改需求"的测试（当天上手）

Agent 跑长任务时的典型事故，不是第一句没听懂，而是中途你改了主意，它要么改错地方，要么把不该动的也一起改了。StreamEval 基准用的正是这个思路。当天就能照做：

1. **设计一条会中途改需求的用例**：别只给一次指令，把需求排到时间线上——比如"先应用红色披风 → 第 10 秒换成金色 → 第 20 秒撤销修改"。关键是要同时包含"要改什么"和"不能动什么"；
2. **分两项打分**：一是"指令跟随"（该改的对象改对了没有），二是"完整成功"（背景、人物动作、此前有效的修改有没有被连带破坏）。很多 Agent 第一项拿分、第二项全丢，只看总分会完全误判；
3. **每个用例独立跑三次，再按会话时长分组汇总**：单次生成偶然性很大，跑三次能看出是稳定能力还是运气；按 15 秒 / 60 秒 / 300 秒分组，还能看出它到底能撑多久。

适合实时视频、数字人，也适合一切"边跑边改"的长流程 Agent——把"中途插话"当成一项正式能力来测，而不是上线后等用户来踩。

> 注释：**指令跟随 vs 完整成功** 前者只问"你让它改的东西改了没"，后者还要追问"没让它动的地方是不是也没动"。两者分开打分，才能看出 Agent 是真的听懂了，还是顺手把摊子掀了。

## 六、AI 论文精选

**《StreamEval：流式交互视频生成的首个公开基准》（arXiv:2610.28402）**

实时交互视频是今年最热的方向之一，但评测工具还停留在老框架：给一段提示词，生成一段视频，再看画面清不清楚、动作合不合理。对实时交互系统来说，这套方法测的根本不是最难的部分——用户的指令是连续的，模型必须在"不中断生成"的前提下及时响应新指令，同时保持人物身份、已有场景和此前所有有效修改不变。清华大学、NVIDIA、CMU、UC Berkeley、普林斯顿、NUS 等机构联合提出 StreamEval，覆盖数字人对话、虚拟人表演、世界生成、指令编辑与参考编辑五类任务，共 300 个用例、单次会话从 15 秒到 300 秒；输入按时间逐步到达，模型事先看不到后面的要求；每个用例对相应模型独立运行三次，再按预定时长分组汇总，以降低单次生成的偶然性。基准还把"指令跟随"与"完整编辑成功"分开评分——改变了正确的对象只算前者，完整成功还要求不该变的地方确实没变。结果相当扎心：38 个模型、49 种任务配置跑下来，最高分仅 15 分；画面质量、指令执行与长时间连续性并不总是同步提升，部分模型画面稳定、音画同步不错，面对连续指令却难以准确完成动作或编辑要求。讲什么：第一次给"边生成边改"这件事立了尺子，而整条赛道都没及格。有什么用：做实时视频、数字人、世界模型的团队，可以直接拿这套公开代码与数据集定位自己到底卡在哪一环。

**《MOSAIC：面向会话智能体长期记忆与跨模态推理的全模态基准》（arXiv:2610.29249）**

全模态助手要记住的不只是用户说了什么，还包括用户展示了什么、传达了什么。但现有长期记忆基准大多是文本加图像的组合，且往往只考"能不能把相关信息捞出来"。来自香港科技大学等机构的作者提出 MOSAIC：一个包含 923 个问题的全模态基准，建立在人物设定一致的多会话历史之上，横跨文本、图像、视频与音频四种模态。它的设计重点不是打分，而是诊断——把记忆过程拆成写入、检索、投递、阅读四个阶段，用来定位会话智能体究竟在哪一步把证据弄丢了。讲什么：记忆失败从来不是一个笼统的"记性差"，而是可以在流水线上精确定位的断点。有什么用：做长期记忆模块的团队，可以先用它判断该优化写入策略还是检索策略，而不是盲目加向量库。

**《多模态具身智能体：从电脑操作到机器人操作的统一能力视角》（PAPAV，arXiv:2610.30108）**

多模态智能体通过推理、记忆、工具与反馈维持交互，最典型的两类形态是电脑操作智能体与机器人。这篇论文把两者放进同一套框架比较，定义了"多模态具身智能体"（MMEA）：把多模态任务推理与物理行动耦合，并根据反馈修正决策的系统。作者提出 PAPAV 框架，用五个能力维度刻画它——感知状态（Perceive）、预判动作效果（Anticipate）、规划路径（Plan）、执行操作（Act）、验证结果（Verify）。基于 64 个基准的统计发现了一个明显偏斜：评估高度集中在 Act 环节，只有 5 个基准评估 Anticipate、3 个评估 Verify。论文还归纳了五项物理约束（从部分可观测性到不可验证的结果），指出机器人场景比电脑操作场景更难回退错误——改错一个文件可以撤销，把杯子摔了不行。讲什么：具身智能的评测严重偏科，最该考的"预判"和"验证"几乎没人考。有什么用：做具身方向的人可以对照这份清单，先看看自己的评估盲区在哪。
